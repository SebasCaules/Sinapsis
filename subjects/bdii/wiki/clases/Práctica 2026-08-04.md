# Práctica del 04/08 — persistencia políglota, Docker y MySQL

## Resumen general

Primera práctica de la cursada (martes 04/08, presencial), del deck `BDD II - Clase I.pdf`: persistencia políglota, introducción a Docker, preparación del entorno y primera parte de los TP1, TP2 y TP3.

**Persistencia políglota** es usar distintas tecnologías para almacenar datos: la traslación a bases de datos de la *programación políglota* (Neal Ford, 2006). Un único tipo de base para todo puede no ser performante y lo habitual es combinar varios; el problema pasa a ser elegir el motor adecuado, y la grilla para justificarlo son seis factores: **tipo** (relacional o NoSQL), **durabilidad**, **disponibilidad**, **consistencia**, **escalabilidad** y **seguridad**. Es el eje del parcial y del TP especial: el objetivo declarado de la materia es aprender a elegir bien una base de datos para un problema concreto.

**Docker** ejecuta aplicaciones en contenedores: la *imagen* es el paquete ejecutable y el *contenedor*, su instancia en tiempo de ejecución. A diferencia de una máquina virtual, que carga un guest OS completo sobre un hipervisor, el contenedor comparte el kernel del host.

El motor de la cursada es **MySQL 9.7.2** en un contenedor (`docker pull mysql:9.7.2` y `docker run` con base `mydb`, usuario `myuser`, puerto 3306); se entra con `docker exec -it MyMySql bash` y `mysql -u myuser -p`, o con Workbench o DataGrip.

Para el parcial: TP1 (modelos/DER), TP2 (creates) y TP3 (SQLs simples) son sobre MySQL, como toda la primera mitad del cronograma. PostgreSQL, HBase y MongoDB, que el programa oficial asigna a los primeros TPs, no se dictan ahí: ante un conflicto de tema o de motor, gana el cronograma.

## Marco conceptual: persistencia políglota

> [!quote] Tus definiciones, de `Clase I.md`
> **Programación políglota**: cuando se usa más de un lenguaje en un mismo proyecto.
> **Persistencia políglota**: cuando se usan diferentes tecnologías para almacenar datos.

**Programación políglota** (término de **Neal Ford, 2006**): mezclar lenguajes en un proyecto para
aprovechar el más adecuado a cada necesidad. Ejemplo de la cátedra: Java es muy potente en el back,
pero malo —o complejo— para el front / interfaces de usuario.

**Persistencia políglota**: lo mismo aplicado a las bases de datos: la aplicación se comunica con
**distintos tipos** de base, en cada caso la que mejor se adapta al almacenamiento. Un único tipo para
todo puede resultar no del todo performante; cada vez es más común combinar varios y más raro usar
uno solo.

### El desafío: elegir el motor adecuado

Elegir el tipo de base para un problema de negocio es cada vez más complejo por la cantidad de tipos
disponibles. Es el objetivo declarado del programa —"aprender a tomar buenas decisiones a la hora de
elegir una base de datos para resolver un problema concreto"— y el eje del parcial y del TP especial;
estos seis factores son la grilla para justificar la elección:

| Factor | Qué se evalúa |
| --- | --- |
| **Tipo** | Relacional vs. NoSQL (columnar, key-value, grafos, documentos, entre otras) |
| **Durabilidad** | Que el dato sobreviva a fallas |
| **Disponibilidad** | Que el sistema responda ante caídas parciales |
| **Consistencia** | Qué tan actualizada es la vista del dato |
| **Escalabilidad** | Cómo crece ante más carga / más datos |
| **Seguridad** | Control de acceso y protección del dato |

**Arquitectura típica** (diagrama del slide): una capa de aplicaciones rutea cada tipo de dato a un
motor distinto — session data → Key/Value, logs → Columnar, product info → Document, customer/agent
relationships → Graph, analytics → Hadoop, transactional data → RDB.

## Marco conceptual: Docker

Plataforma open-source basada en contenedores Linux, para desarrollar, implementar y ejecutar
aplicaciones con **contenedores**. Beneficios de contenerizar:

- **Flexibles** — hasta las apps más complejas se contenerizan.
- **Livianos** — usan el kernel del host directamente (a diferencia de las VMs).
- **Adaptables** — actualizaciones sobre la marcha, sin bajar la app.
- **Portables** — se construyen localmente, se implementan en la nube y corren en cualquier SO.
- **Escalables** — más capacidad y réplicas distribuidas automáticamente.

### Imagen vs. contenedor

- **Imagen:** paquete ejecutable con todo lo necesario para ejecutar una aplicación — código fuente,
  runtime, bibliotecas, variables de entorno y archivos de configuración.
- **Contenedor:** instancia en **tiempo de ejecución** de una imagen — una imagen con estado, o un
  proceso de usuario.

Repositorio de imágenes: <https://hub.docker.com/search?q=&type=image&badges=official>

### Contenedores vs. máquinas virtuales

| | Contenedor | Máquina virtual |
| --- | --- | --- |
| **Kernel** | Comparte el del host | Guest OS completo por VM |
| **Aislamiento** | Proceso discreto | Hipervisor + virtualización de recursos |
| **Peso** | No ocupa más memoria que cualquier otro ejecutable | Entorno con más recursos de los que la mayoría de las apps necesitan |
| **Stack** | App → Bins/Libs → Docker Engine → Host OS → Server | App → Bins/Libs → Guest OS → Hypervisor → Host OS → Server |

## Setup del entorno

La cátedra usa **MySQL 9.7.2**: contenedor Docker (recomendado) o instalación directa desde
<https://dev.mysql.com/downloads/mysql/>.

### Requisitos de Docker Desktop (Windows)

- WSL 2 habilitado.
- Windows 11 64-bit Enterprise/Pro/Education 23H2 (build 22631) o superior, **o**
  Windows 10 64-bit Enterprise/Pro/Education 22H2 (build 19045).
- Features Hyper-V y Containers habilitados.
- Procesador 64-bit con SLAT, 8 GB RAM, virtualización habilitada en BIOS/UEFI.

En **Linux** basta Docker Engine, sin Docker Desktop; después de instalar, agregar el usuario al
grupo `docker` para evitar errores de permisos y el uso de `sudo`.

### Verificar la instalación

```bash
docker version
```

```bash
docker run hello-world
```

### Levantar MySQL

```bash
docker pull mysql:9.7.2
```

```bash
docker run --name MyMySql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=mydb -e MYSQL_USER=myuser -e MYSQL_PASSWORD=mysecretpassword -p 3306:3306 -d mysql:9.7.2
```

### Conectarse desde el cliente de línea de comandos

```bash
docker exec -it MyMySql bash
```

```bash
mysql -u myuser -p
```

### Clientes gráficos (alternativas)

- **MySQL Workbench Community** — <https://dev.mysql.com/downloads/workbench/>
  Connection Method `Standard (TCP/IP)`, Hostname `127.0.0.1`, Port `3306`, Username `myuser`,
  Default Schema `mydb`.
- **DataGrip (JetBrains)** — Data Source MySQL, descargar los drivers correspondientes.
  Host `localhost`, Port `3306`, User `myuser`, Database `mydb`,
  URL `jdbc:mysql://localhost:3306/mydb`.

### Comandos Docker de referencia

```bash
docker image ls  # o: docker images  — lista imágenes descargadas
docker container ls --all # o: docker ps -a  — lista contenedores (--all incluye los detenidos)
docker stop <container_name>
docker start <container_name>
```
