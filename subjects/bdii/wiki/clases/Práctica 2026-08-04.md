## Marco conceptual: persistencia políglota

> [!quote] Tus definiciones, de `Clase I.md`
> **Programación políglota**: cuando se usa más de un lenguaje en un mismo proyecto.
> **Persistencia políglota**: cuando se usan diferentes tecnologías para almacenar datos.
>
> Las dos secciones que siguen las amplían con lo que agregan los slides.

### Programación políglota

**Definición:** cuando se usa más de un lenguaje en un mismo proyecto. Las aplicaciones se codifican
en una mezcla de lenguajes distintos, con el objetivo de aprovechar el más adecuado para cada
necesidad.

**Origen:** término introducido por **Neal Ford en 2006**.

**Ejemplo de la cátedra:** Java es muy potente para codificar funcionalidades en el back, pero no es
bueno —o es complejo— a la hora de programar el front / interfaces de usuario.

### Persistencia políglota

**Definición:** cuando se usan diferentes tecnologías para almacenar datos. El mismo concepto de
programación políglota aplicado a las bases de datos: una aplicación se comunica con **distintos
tipos** de bases de datos, usando en cada caso la que mejor se adapta a la necesidad de
almacenamiento.

**Por qué importa:**

- Usar un único tipo de base de datos para todo puede resultar en una solución no del todo
  performante.
- Cada vez es más común ver varios tipos de bases usados en conjunto; cada vez es más raro el uso de
  uno solo.

### El desafío: elegir el motor adecuado

Decidir cuál es el tipo de base más adecuado para resolver un problema de negocio es cada vez más
complejo por la cantidad de tipos disponibles. **Factores de decisión:**

| Factor | Qué se evalúa |
| --- | --- |
| **Tipo** | Relacional vs. NoSQL (columnar, key-value, grafos, documentos, entre otras) |
| **Durabilidad** | Que el dato sobreviva a fallas |
| **Disponibilidad** | Que el sistema responda ante caídas parciales |
| **Consistencia** | Qué tan actualizada es la vista del dato |
| **Escalabilidad** | Cómo crece ante más carga / más datos |
| **Seguridad** | Control de acceso y protección del dato |

> [!tip] Esto es el eje del parcial y del TP especial
> El programa dice explícitamente que el objetivo de la materia es "aprender a tomar buenas
> decisiones a la hora de elegir una base de datos para resolver un problema concreto". Estos seis
> factores son la grilla con la que se justifica esa elección.

**Arquitectura típica** (diagrama del slide): una capa de aplicaciones que rutea cada tipo de dato a
un motor distinto — session data → Key/Value, logs → Columnar, product info → Document,
customer/agent relationships → Graph, analytics → Hadoop, transactional data → RDB.

## Marco conceptual: Docker

**Definición:** plataforma para desarrolladores y administradores de sistemas, diseñada para
desarrollar, implementar y ejecutar aplicaciones con **contenedores**. Es un proyecto open-source
basado en contenedores Linux.

**Beneficios de contenerizar:**

- **Flexibles** — aún las aplicaciones más complejas pueden ser contenerizadas.
- **Livianos** — los contenedores usan el kernel del host en forma directa (en contraste con las VMs).
- **Adaptables** — se pueden implementar actualizaciones y mejoras sobre la marcha, sin bajar la app.
- **Portables** — se construyen localmente, se implementan en la nube y corren en cualquier entorno y SO.
- **Escalables** — se puede incrementar la capacidad y distribuir réplicas automáticamente.

### Imagen vs. contenedor

- **Imagen:** paquete ejecutable que incluye todo lo necesario para ejecutar una aplicación — código
  fuente, runtime, bibliotecas, variables de entorno y archivos de configuración.
- **Contenedor:** instancia en **tiempo de ejecución** de una imagen. Es en lo que se convierte la
  imagen en memoria cuando se ejecuta — es decir, una imagen con estado, o un proceso de usuario.

Repositorio de imágenes: <https://hub.docker.com/search?q=&type=image&badges=official>

### Contenedores vs. máquinas virtuales

| | Contenedor | Máquina virtual |
| --- | --- | --- |
| **Kernel** | Comparte el del host | Guest OS completo por VM |
| **Aislamiento** | Proceso discreto | Hipervisor + virtualización de recursos |
| **Peso** | No ocupa más memoria que cualquier otro ejecutable | Entorno con más recursos de los que la mayoría de las apps necesitan |
| **Stack** | App → Bins/Libs → Docker Engine → Host OS → Server | App → Bins/Libs → Guest OS → Hypervisor → Host OS → Server |

## Setup del entorno

La cátedra usa **MySQL 9.7.2** como base de datos relacional. Dos opciones para el servidor:
contenedor Docker (recomendado) o instalación directa desde <https://dev.mysql.com/downloads/mysql/>.

### Requisitos de Docker Desktop (Windows)

- WSL 2 habilitado.
- Windows 11 64-bit Enterprise/Pro/Education 23H2 (build 22631) o superior, **o**
  Windows 10 64-bit Enterprise/Pro/Education 22H2 (build 19045).
- Features Hyper-V y Containers habilitados.
- Procesador 64-bit con SLAT, 8 GB RAM, virtualización habilitada en BIOS/UEFI.

En **Linux** no hace falta Docker Desktop, solo Docker Engine. Después de instalar, agregar el
usuario al grupo `docker` para evitar errores de permisos y el uso de `sudo`.

### Verificar la instalación

```bash
docker version
```

```bash
docker run hello-world
```

### Levantar MySQL

```bash
docker pull mysql:9.7.2
```

```bash
docker run --name MyMySql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=mydb -e MYSQL_USER=myuser -e MYSQL_PASSWORD=mysecretpassword -p 3306:3306 -d mysql:9.7.2
```

### Conectarse desde el cliente de línea de comandos

```bash
docker exec -it MyMySql bash
```

```bash
mysql -u myuser -p
```

### Clientes gráficos (alternativas)

- **MySQL Workbench Community** — <https://dev.mysql.com/downloads/workbench/>
  Connection Method `Standard (TCP/IP)`, Hostname `127.0.0.1`, Port `3306`, Username `myuser`,
  Default Schema `mydb`.
- **DataGrip (JetBrains)** — Data Source MySQL, descargar los drivers correspondientes.
  Host `localhost`, Port `3306`, User `myuser`, Database `mydb`,
  URL `jdbc:mysql://localhost:3306/mydb`.

## Comandos Docker de referencia

```bash
docker image ls          # o: docker images  — lista imágenes descargadas
docker container ls --all # o: docker ps -a  — lista contenedores (--all incluye los detenidos)
docker stop <container_name>
docker start <container_name>
```
